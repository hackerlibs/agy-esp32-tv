# 03. 硬件仪器实战调试指南（万用表 / USB-TTL / 示波器 / 逻辑分析仪）

做嵌入式硬件最怕「盲猜改代码」。你手头已经有**万用表、示波器、USB-TTL**，再加上一块几十块钱的**逻辑分析仪**，就拥有了排查数字+模拟电路的全部利器。

先记住四种仪器的黄金分工：

| 仪器 | 擅长看什么（直觉类比） | 什么时候拿它？ |
|---|---|---|
| **万用表** | 静态直流电压、通断、阻值、平均电流 | 通电前查短路、通电后查 3.3V、测背光极性、蜂鸣档顺藤摸瓜查未知引脚 |
| **USB-TTL** | 底层串口文本日志 | USB 虚拟串口消失、芯片反复重启、看 Mask ROM 报错码（`boot:0x...`） |
| **示波器** | **真实模拟波形**（幅值、纹波、上升沿、振铃过冲、单次脉冲、PWM 占空比） | 电源跌落、背光 PWM 验证、RST 20ms 脉冲、检查 27MHz SPI 波形畸变与 Mode 3 相位 |
| **逻辑分析仪** | **多通道长时间数字 0/1 抓取 + 协议自动解码**（直接把波形翻译成 `0x11 / 0x2A / 0x2C` 字节！） | 核对 ST7789 初始化指令序列、抓取原厂固件 SPI 通信逆向未知屏幕、定位错字节/漏命令 |

## 1. 万用表实战（通电前必做 + 30 秒排障）

### 1.1 通电前的「保命三测」（断电状态下）
1. **电阻档测 `3V3` 对 `GND`**：正常应在几百 Ω 以上（刚接上表笔时电容充电数值会从小变大）。如果蜂鸣档直接响（< 10Ω），**绝对不要插 USB！**先查焊锡连桥或模块正反接。
2. **蜂鸣档查连线**：从 ESP32 芯片引脚（或开发板排针）测到屏幕模块焊盘，逐一确认 `SCLK / MOSI / DC / RST / BL / GND / 3V3` 通断正确、相邻脚无短路。
3. **追踪未知成品板的引脚**（如果你拿到一块没原理图的小电视板子）：
   - 断电，黑表笔顶住屏幕 FPC 排线焊盘（如 SCL 脚），红表笔沿着 ESP32-C3 周围逐个引脚划过，蜂鸣器响就立刻确定对应 GPIO 编号！

### 1.2 通电后的关键电压点（直流电压档，黑表笔接 GND）
- **3V3 电源轨**：实测应在 **`3.20V ~ 3.38V`**。若低于 `3.0V`，说明 LDO 过载或 USB 线压降太大。
- **EN（复位脚）**：正常运行时为 **`~3.3V`**（板载 10kΩ 上拉电阻 + 0.1~1uF 延时电容）。如果测到 `0V` 说明被拉死在复位态。
- **GPIO9（Boot 脚）**：正常运行时为 **`~3.3V`**。按下 BOOT 键时变 `0V`。
- **GPIO2（本项目 DC 脚）**：复位瞬间应为高电平，正常刷屏时因为快速在命令(0)和数据(1)之间切换，万用表会读到一个接近 **`2.8V ~ 3.3V`** 的平均电压。
- **背光脚 GPIO1 实测极性（30 秒锁定暗屏元凶！）**：
  - 跑完 `python3 host/agy_tv.py bl 100` 后，用万用表直流电压档测 `GPIO1` 对 `GND`：
    - 测到 **`~0.0V`** 且屏幕很亮 → **低电平有效（PNP / P-MOS）**（本项目硬件）；
    - 测到 **`~3.3V`** 且屏幕很暗 → 占空比反了！发一条 `python3 host/agy_tv.py bl --inv 1`（或 `0`），立刻看到电压翻转、屏幕变亮。
  - 再测 `LED_A`（背光阳极）和 `LED_K`（阴极）压差：正常点亮时白光 LED 两端压降约 **`2.8V ~ 3.1V`**。如果压差接近 `0V`，说明背光供电断路或限流电阻/三极管没导通。

## 2. USB-TTL 串口模块实战（救命诊断口）

本项目平时靠 ESP32-C3 内置的 USB-Serial/JTAG（GPIO18/19）直接走一根 Type-C 线通信。但遇到以下情况时，**外接 USB-TTL 是唯一能看到真相的工具**：
- 固件一启动就崩溃/死循环，把内置 USB 外设带崩，电脑根本枚举不出串口；
- 你自己画板子/买裸模组，没有引出 USB `D+/D-`；
- 想在不干扰 USB DTR/RTS 复位逻辑的前提下，纯粹旁听芯片上电第一毫秒的 Mask ROM 输出。

### 2.1 接线规范（务必确认 3.3V！）
1. **先把 USB-TTL 模块上的跳线帽拨到 `3.3V`！** 用万用表确认模块 `TXD` 空载电压是 `3.3V` 而不是 `5V`。
2. 交叉连接三根线（ESP32 由自己的 USB 供电，**不要把 USB-TTL 的 VCC 接到 ESP32 3V3**，以免两个电源打架）：

```text
  USB-TTL 模块                 ESP32-C3
  ─────────────               ─────────────────
  GND   ────────────────────► GND（必须共地！）
  RXD   ◄──────────────────── GPIO21 (U0TXD)
  TXD   ────────────────────► GPIO20 (U0RXD)
```

3. 电脑端以 **`115200 bps, 8N1, 无流控`** 打开 USB-TTL 对应的串口（如 `screen /dev/ttyUSB0 115200` 或 `tools/monitor.sh /dev/ttyUSB0`）。

### 2.2 读懂 Mask ROM 启动码
按一下开发板 `RST`（或短暂把 `EN` 碰一下 `GND`），你会看到 ROM 打印的核心两行：

- **正常从 Flash 启动**：
  ```text
  rst:0x1 (POWERON),boot:0xd (SPI_FAST_FLASH_BOOT)
  I (24) boot: ESP-IDF v5.5 2nd stage bootloader
  I (121) main: AGY TV 2.0.0 booting
  ```
- **进入下载模式**（手动方法：先按住 `BOOT`/拉低 `GPIO9`，点按 `RST`/`EN`，再松开 `BOOT`）：
  ```text
  rst:0x1 (POWERON),boot:0x5 (DOWNLOAD(USB/UART0/1))
  waiting for download
  ```
- **常见异常一眼识别**：
  - `Brownout detector was triggered` → 3.3V 供电不足或缺少退耦电容；
  - `invalid header: 0xffffffff` → Flash 是空的，或刷错偏移地址（ESP32-C3 bootloader 必须在 `0x0`，不是老款 ESP32 的 `0x1000`！）；
  - 反复出现 `TG0WDT_SYS_RST` / `Panic` → 代码崩溃或 SPI 死等，看回溯日志定位。

## 3. 示波器实战（模拟电路功底的主场！）

很多纯软件背景的人遇到「代码没错但屏幕不亮 / 偶尔花屏」束手无策，但用示波器往往 **2 分钟一锤定音**。

> **探头准备**：测 ≥10MHz 的 SPI 信号时，务必把示波器探头拨到 **`10X` 衰减档**（`1X` 档输入电容高达 ~100pF，会把 27MHz 方波直接滤成三角波甚至把信号拉死！），并尽量用短接地弹簧或短地夹就近接 GND。

### 场景 1：检查 3.3V 电源纹波与跌落
- **设置**：耦合选 **`AC`**（交流耦合看纹波）或 **`DC`**（看绝对跌落），时基 `200 us/div`，垂直 `100 mV/div`。
- **判断标准**：
  - 正常刷屏时 3.3V 纹波峰峰值应 **< 100 mV**；
  - 如果发现背光开启或刷屏瞬间电压向下掉出一个大坑（> 300mV），马上在屏幕 `VCC-GND` 并一颗 `10uF + 0.1uF` 电容，或换更粗的供电线。

### 场景 2：测量背光 PWM（GPIO1）—— 一眼抓住极性陷阱
- **设置**：`DC` 耦合，`1 V/div`，时基 **`50 us/div`**，边沿触发（上升沿，触发电平 `1.6V`）。
- **正常预期**：
  - 频率读数应为 **`5.00 kHz`**（周期 **`200 us`**），幅值 `0V ~ 3.3V`；
  - 在电脑端依次跑 `python3 host/agy_tv.py bl 20`、`bl 50`、`bl 80`：
    - **低电平有效（`inv=1`）**时：`bl 20` 看到的是 20% 低电平（40us 低 + 160us 高）；`bl 80` 是 80% 低电平（160us 低 + 40us 高）；`bl 100` 是一条 `0V` 直线；
    - 如果发现占空比变化方向与屏幕明暗相反，立刻确认极性反了！

### 场景 3：单次触发（Single）抓取上电复位脉冲（RST / GPIO6）
ST7789 要求硬件复位脉冲低电平持续至少 10us（本固件按原厂用 **`20 ms`** 低电平 + **`150 ms`** 稳定延时）。
- **设置**：`DC` 耦合，`1 V/div`，时基 **`10 ms/div`**，触发模式选 **`Single`（单次触发）** + **下降沿** + 触发电平 `1.6V`。
- **操作**：按示波器 `Single` 进入等待，然后重启 ESP32（`python3 host/agy_tv.py send "ZTV1 C reboot"`）。
- **验证**：屏幕上会稳稳冻住一个 `3.3V → 0V → 3.3V`、宽度精确为 **`20 ms`** 的负脉冲。如果没抓到，说明 `RST` 线虚焊、引脚配错或芯片根本没跑进 `panel_init()`。

### 场景 4：双通道核对 SPI Mode 3 与信号完整性（SCLK + MOSI）
- **通道接法**：`CH1` 接 `SCLK (GPIO3)`，`CH2` 接 `MOSI (GPIO5)`（若为 4 通道示波器，`CH3` 接 `DC (GPIO2)`）。
- **设置**：`10X` 探头，`2 V/div`，时基先设 **`50 ns/div`**（27MHz 周期 ≈ `37 ns`），`CH1` 下降沿触发（电平 `1.6V`）。
- **重点看三件事**：
  1. **SPI Mode 3（`CPOL=1, CPHA=1`）波形特征**：
     ```text
     SCLK (Mode 3): ───┐   ┌───┐   ┌───┐   ┌───┐   ┌──────── (空闲为高电平 3.3V!)
                       └───┘   └───┘   └───┘   └───┘
                               ▲       ▲       ▲
                            上升沿采样 (CPHA=1: MOSI在下降沿变化，上升沿保持稳定)
     MOSI:          ─────X───────X───────X───────X──────────
     ```
     确认无数据传输时 `SCLK` 停在 **3.3V（高电平）**，且 `MOSI` 在 `SCLK` **上升沿**正中间是稳稳的 `0V` 或 `3.3V`（建立/保持时间充足）。
  2. **模拟信号质量（过冲与上升沿）**：
     - 如果 27MHz 下方波变成正弦波/三角波，或过冲超过 `4.2V` / 下冲低于 `-0.8V` 且剧烈振铃，说明面包板杜邦线太长或地线太绕；
     - 解决办法：剪短杜邦线、加紧贴的 GND 回流线、在 SCLK/MOSI 源端串 `33Ω` 电阻，或先把 `ZTV_LCD_SPI_CLOCK_KHZ` 降到 `10000`（10MHz）。
  3. **DC 引脚配合**：放慢时基到 `20 us/div`，观察 `DC (CH3)` 在每次发新窗口命令（`0x2A CASET` / `0x2B RASET` / `0x2C RAMWR`）时短暂拉低（1 字节命令），紧接着拉高传输成片像素数据。

## 4. 逻辑分析仪实战（从零抓包解码 + 逆向未知屏幕）

示波器看波形质量无敌，但它只能看几十微秒到几毫秒，而且要肉眼数 `0` 和 `1` 翻译成十六进制太痛苦。这时**逻辑分析仪**就是降维打击！

### 4.1 需要买什么逻辑分析仪？
入门完全不需要几千块的高端仪器：
- 淘宝搜 **「24MHz 8 通道 逻辑分析仪」**（基于 Cypress FX2LP CY7C68013A 的小黑盒，约 **¥25 ~ ¥45**）；
- 搭配免费开源软件 **[PulseView (sigrok)](https://sigrok.org/wiki/Downloads)**（macOS / Linux / Windows 全平台支持，内置 100+ 种协议解码器，包括 SPI 和 UART）。

### 4.2 最核心的一条铁律：采样率 ≥ 4 倍 SPI 时钟！
> **新手最常踩的坑**：24MHz 逻辑分析仪**绝对采不到** 27MHz 的 SPI 信号！（根据奈奎斯特采样定理 + 数字信号相位裕量，逻辑分析仪的采样率必须至少是 SPI 时钟的 **4 ~ 8 倍**。）

**正确调试姿势**：
1. 调试阶段先在 `idf.py menuconfig` → `AGY TV` → `LCD panel` → `SPI pixel clock in kHz` 里把 SPI 时钟临时降到 **`2000`（2 MHz）** 或 **`4000`（4 MHz）** 并重新刷机；
2. 此时 24MHz 采样率 ÷ 2MHz SPI = **12 倍过采样**，每一个时钟脉冲都有 12 个采样点，解码 100% 精准！
3. 确认所有初始化指令和像素协议完全正确、屏幕点亮后，再把时钟调回 `27000`（27MHz）享受全速刷新！

*(注：如果是逆向原厂 27MHz 固件而无法改时钟，就需要 100MHz~400MHz 的逻辑分析仪，如 DSLogic Plus / Kingst LA1010 / Saleae Logic Pro。)*

### 4.3 接线方法（5 通道 + GND）

```text
  逻辑分析仪通道       接到电路测试点          在 PulseView 里重命名
  ──────────────      ──────────────────     ───────────────────
  CH0                 GPIO3 (SCLK)           SCLK
  CH1                 GPIO5 (MOSI)           MOSI
  CH2                 GPIO2 (DC)             DC
  CH3                 GPIO6 (RST)            RST
  CH4                 GPIO1 (BL)             BL
  GND                 ESP32 GND（必须接！）   GND
```

*(如果你的屏幕用了 CS 脚，再接 `CH5 → CS`。)*

### 4.4 在 PulseView 中抓包并解码 ST7789 初始化流程
1. **配置采样参数**：
   - 采样率设为 **`24 MHz`**；
   - 采样点数设为 **`50 M samples`**（约 2 秒窗口，足够完整覆盖 ESP32 上电复位 + 500ms `SLPOUT` + 初始化 + 第一帧刷屏！）。
2. **设置触发条件**：
   - 点击 `RST (CH3)` 通道标签，选择 **下降沿触发（Falling Edge `↓`）**。
3. **开始抓包**：
   - 点击左上角 **`Run`**（逻辑分析仪开始等待触发）；
   - 重启 ESP32（按板子 `RST` 或发 `ZTV1 C reboot`）；
   - 2 秒后 PulseView 自动抓完并停止！
4. **添加 SPI 协议解码器**：
   - 点工具栏上的黄绿图标 **`Add protocol decoder`** → 搜索并双击 **`SPI`**；
   - 点击新出现的 `SPI` 解码轨道进行配置：
     - `CLK` → `SCLK (CH0)`
     - `MOSI` → `MOSI (CH1)`
     - `CS#` → 若无 CS 脚保持 `-`（留空）
     - `Clock polarity (CPOL)` → **`1`**
     - `Clock phase (CPHA)` → **`1`**（Mode 3！）
     - `Bit order` → **`msb-first`**
     - `Word size` → **`8`**

### 4.5 逐字节核对本项目的正确初始化序列
放大抓到的波形，顺着 `RST` 拉高后 `150 ms` 的位置往后看，配合 `DC` 引脚高低电平（`DC=0` 是命令，`DC=1` 是参数/像素），你应该会在 PulseView 的 SPI 解码轨上清清楚楚看到下面这串十六进制数（与 [main/panel.c](../main/panel.c) 逐字节对应）：

| 时刻 | `DC` 电平 | SPI 解码字节 (Hex) | ST7789 指令含义 |
|---|---|---|---|
| `RST` 拉高后 +150ms | `0` (命令) | `0x11` | `SLPOUT` 退出睡眠（之后等 500ms） |
| +500ms | `0` → `1` | `0x3A` → `0x55` | `COLMOD` 设为 16-bit RGB565 格式 |
| +10ms | `0` → `1` | `0x36` → `0x00` | `MADCTL` 扫描方向（旋转 0°） |
| 紧接着 | `0` → `1` | `0x2A` → `0x00 0x00 0x00 0xEF` | `CASET` 列窗口 `0 .. 239 (0xEF)` |
| 紧接着 | `0` → `1` | `0x2B` → `0x00 0x00 0x00 0xEF` | `RASET` 行窗口 `0 .. 239 (0xEF)` |
| 紧接着 | `0` | `0x21` | `INVON` 开启反相（IPS 屏必须） |
| +10ms | `0` | `0x13` | `NORON` 正常显示模式 |
| +10ms | `0` | `0x29` | `DISPON` 打开显示输出（之后等 500ms） |
| 首帧刷屏 | `0` → `1` | `0x2C` → `[115200 字节 RGB565]` | `RAMWR` 开始灌入像素数据 |

**逻辑分析仪的另一个绝招——逆向一块陌生屏幕**：
如果你买到了一块卖家只给 Arduino 编译好固件、不给初始化代码的屏幕，只要把逻辑分析仪挂在 `SCLK / MOSI / DC / RST / BL` 上，让原厂固件跑一次开机，用 PulseView 把上面这张表完整抄下来填进 `panel.c`，哪怕没有数据手册也能 100% 点亮！

## 5. 故障排查决策树（遇到问题按顺序查）

```text
通电后屏幕表现
 ├─ ① 屏幕完全漆黑（连微微泛白/灰底都没有）
 │    ├─ 查背光！跑 `python3 host/agy_tv.py bl` 看返回值，再用示波器/万用表测 GPIO1
 │    │   └─ 测 LED_A/LED_K 压差：无压差 → 查背光极性 (`bl --inv 0/1`) 或背光三极管供电
 │    └─ 背光确认亮了但全黑（能看到背光微透灰底）
 │        ├─ 串口跑 `ZTV1 C ping` 和 `ZTV1 C stats`：
 │        │   ├─ 无回复 → 用 USB-TTL 接 GPIO20/21 看是否卡在 ROM 下载模式或未启动
 │        │   └─ 有回复且 frames 在涨 → 固件在跑，是 SPI 通信问题：
 │        │       1) 示波器看 RST 有无 20ms 复位脉冲；
 │        │       2) 示波器看 SCLK/MOSI 有无波形、是否 Mode 3、过冲是否严重；
 │        │       3) 降频到 4MHz 用逻辑分析仪对照第 4.5 节核对初始化命令。
 │
 ├─ ② 屏幕特别暗，凑近/关灯才能勉强看到字
 │    └─ 经典背光极性反了！执行 `python3 host/agy_tv.py bl --inv 1`（或 `0`），
 │       并用示波器确认 GPIO1 占空比方向。
 │
 ├─ ③ 屏幕纯白屏（背光很亮但没有任何图像）
 │    └─ 背光正常，但 ST7789 没收到初始化指令或没复位：
 │        查 RST / DC / SCLK / MOSI 是否接反，以及无 CS 屏是否误设成了 SPI Mode 0。
 │
 ├─ ④ 能显示图像，但颜色反了（黑底变白底、红蓝颠倒）
 │    ├─ 黑底变白底 → IPS 反相设置不对，在 menuconfig 切换 `ZTV_LCD_INVERT` (`INVON 0x21`)
 │    └─ 红蓝颠倒 → `MADCTL (0x36)` 的 BGR bit (bit 3 = `0x08`) 差异，调整 `panel.c` 中的 `MADCTL[]`
 │
 ├─ ⑤ 图像歪了 / 倒了 / 旋转 90°
 │    └─ 在线执行 `python3 host/agy_tv.py send "ZTV1 C rot=0"`（试 0/1/2/3），
 │       找到正确方向后写入 menuconfig 的 `ZTV_LCD_ROTATION`。
 │
 └─ ⑥ 图像错位、边缘有雪花噪点或偶尔花屏
```

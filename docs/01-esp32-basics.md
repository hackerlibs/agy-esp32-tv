# 01. 从模拟电路走进 ESP32-C3

如果你平时接触的是运放、三极管、稳压电源、RC 滤波这类模拟电路，第一次看 ESP32 往往会觉得「引脚都能复用、烧录还要按按钮、串口怎么既是日志又是下载口」很玄学。这一篇用模拟电路视角把 ESP32-C3 的底层机制拆清楚。

---

## 1. ESP32 家族与本项目的 ESP32-C3

ESP32 不是一颗芯片，而是一个系列（均由乐鑫 Espressif 推出）。常见入门款对比如下：

| 型号 | CPU 架构与主频 | SRAM | 内置 USB 串口 | 特点 |
|---|---|---|---|---|
| **ESP32 (经典款)** | Xtensa 双核 240MHz | 520KB | 无（需外接 CP2102/CH340） | 经典老将，外设多，封装较大 |
| **ESP32-C3（本项目）** | **RISC-V 单核 160MHz** | **400KB** | **有（USB-Serial/JTAG）** | 便宜（~¥8~12）、体积小（QFN32）、省掉 USB 转串口芯片、支持 Wi-Fi + BLE 5 |
| **ESP32-S3** | Xtensa 双核 240MHz | 512KB + 可外挂 PSRAM | 有（USB OTG + Serial/JTAG） | 算力强、可挂 8MB PSRAM，适合更大屏或 LVGL 复杂动画 |

本项目的小电视主控是 **ESP32-C3 (QFN32) rev 0.4 + 4MB Flash**。它能以 20fps 流畅驱动 240×240 RGB565 彩屏，核心原因在于：
- 屏幕一整帧缓冲只需要 `240 × 240 × 2 字节 = 115,200 字节`（约 112.5 KB），在 400KB SRAM 里游刃有余（实测运行后还剩 ~188KB 空闲堆）；
- 硬件 SPI 外设 + DMA 可以把像素直接从内存搬运到屏幕，不靠 CPU 一个像素一个像素地翻转电平。

## 2. 供电与电平：模拟电路视角第一课

### 2.1 严格的 3.3V CMOS 体系
- **工作电压**：ESP32-C3 的 VDD 范围是 **3.0V ~ 3.6V**（典型 **3.3V**）。
- **GPIO 不耐 5V！** 任何输入信号（包括 USB-TTL 的 TX 线！）如果接到 5V 电平，都会通过引脚内部的 ESD 钳位二极管把电流灌进 3.3V 电源轨，轻则逻辑异常、重则永久击穿 IO 口。
- **单引脚驱动能力**：ESP32-C3 单个 GPIO 输出高电平最大约 40mA、灌电流约 28mA，但长期稳定工作建议控制在 **≤ 12~20mA**。**绝对不要用 GPIO 直接驱动 TFT 屏幕的背光 LED 灯串**（通常要 40~80mA），必须经过三极管或 MOS 管开关（详见第 2 篇）。

### 2.2 电源轨与瞬态电流（为什么需要退耦电容）
虽然稳态下 ESP32-C3 不开 Wi-Fi 只跑屏幕大约消耗 **50~100mA**（含背光），但一旦开启 Wi-Fi 发射或背光 PWM 瞬间导通，电流会有 **200~350mA 的微秒级尖峰**：
- 5V USB → 3.3V LDO（如 AMS1117-3.3、ME6211、HT7333，**务必选额定输出 ≥ 500mA** 的 LDO，不要用 150mA 小封装 LDO）；
- 3.3V 电源轨上如果电压瞬间跌到 **2.4V~2.7V 以下**，芯片内部的 **Brownout Detector（欠压复位电路）** 会立刻把芯片复位，你在串口会看到 `Brownout detector was triggered`；
- **退耦电容配置**：LDO 输出端放 `10uF ~ 22uF` 电解/钽/MLCC 电容，ESP32 芯片 VDD 脚和 TFT 屏幕 VCC 脚旁各就近放一颗 `0.1uF (104)` 陶瓷电容。

## 3. GPIO 矩阵与 Strapping（启动配置）引脚陷阱

### 3.1 任意映射的 GPIO 矩阵
传统单片机（如 51、早期 STM32）的 SPI 引脚是写死的；而 ESP32-C3 内部有一张 **GPIO Matrix（交换矩阵）**，可以把 SPI 的 `SCLK`/`MOSI`、PWM 的 `LEDC` 通道路由到几乎任意可用 GPIO。
- 不过 SPI 速度超过 ~26~40MHz 时，优先用 **IOMUX 直连引脚**（延迟更低、波形更干净）。本项目实测原厂使用的 `SCLK=GPIO3`、`MOSI=GPIO5` 在 27MHz 下波形非常稳。

### 3.2 必须背下来的 3 个 Strapping 引脚（开机采样）
芯片上电或 `EN` 复位释放的那一瞬间，内部 Mask ROM 会读取几个特定引脚的高低电平来决定「从 Flash 正常启动」还是「进入串口下载模式」：

| 引脚 | 作用 | 正常启动 Flash 要求 | 进入 ROM 下载模式 | 本项目使用情况 |
|---|---|---|---|---|
| **GPIO9** | Boot 模式选择（内部有弱上拉） | **高电平 (1)** | **低电平 (0)** | 未接外设（悬空即高电平），开发板上的 `BOOT` 按键就是把它拉到 GND |
| **GPIO8** | Boot/ROM 日志控制 | **高电平 (1)** | 必须为高电平 (1) | 未使用 |
| **GPIO2** | Boot 采样脚 | **高电平 (1)** | 需为高电平 (1) | **本项目用作屏幕 DC 脚！** |

> **实操提醒**：因为本项目把 `GPIO2` 用作了屏幕的 `DC` 脚，**千万不要给 GPIO2 接外部强下拉电阻**，否则芯片上电时会进不了正常启动模式！ST7789 的 `DC` 是 CMOS 高阻输入脚，不会把 GPIO2 拉低，所以正常工作完全没问题。

### 3.3 还有哪些引脚不能乱碰？
- **GPIO12 ~ GPIO17**：连接内部/片外 QSPI Flash（存代码和字库），**绝对不可挪作他用**，一动就死机。
- **GPIO18 / GPIO19**：内置 **USB-Serial/JTAG** 的 `D-` 和 `D+`，本项目靠它和电脑通信与烧录，不可复用。
- **GPIO20 / GPIO21**：默认硬件 **UART0**（`RX` / `TX`），是接外部 USB-TTL 看底层启动日志的「救命口」。

## 4. 内置 USB-Serial/JTAG 与「为什么板子有时像变砖」

ESP32-C3 把 USB 转串口和 JTAG 调试器直接做进了硅片里（接在 GPIO18/19），电脑插上 USB 线就会识别出一个 CDC-ACM 虚拟串口（macOS 为 `/dev/cu.usbmodem*`，Linux 为 `/dev/ttyACM*`）。

这个外设内部用串口流控信号 **DTR** 和 **RTS** 控制芯片的复位（`EN`）和下载模式锁存器（等效拉低 `GPIO9`）：

```text
  电脑串口驱动 ──(USB SET_CONTROL_LINE_STATE)──► ESP32-C3 USB-Serial/JTAG
                                                     ├─ DTR=1, RTS=0 ──► 置位下载模式标志
                                                     ├─ DTR=0, RTS=1 ──► 触发芯片复位 (EN 拉低)
                                                     └─ DTR=1, RTS=1 ──► 安全运行态（不触发下载）
```

这就是项目 README 里提到的著名现象：**板子看起来「死」了 / 黑屏无输出**——其实只是某些串口工具打开端口时给出了 `DTR=1, RTS=0` 的组合，把芯片送进了 ROM 下载模式！重新插拔 USB，或用本项目把 DTR/RTS 固定在安全组合的 `tools/monitor.sh` 打开即可瞬间恢复。

## 5. 外设精讲：LEDC PWM 与 SPI + DMA

### 5.1 LEDC PWM（背光调光）
ESP32-C3 的 `LEDC` 外设本质是一个高精度硬件方波发生器。本项目在 [main/panel.c](../main/panel.c) 中的配置：
- **频率**：`5000 Hz`（5kHz，远高于人眼闪烁感知 ~100Hz，手机拍照也不容易出横纹）；
- **分辨率**：`8-bit`（`LEDC_TIMER_8_BIT`），可设占空比范围是 **`0 ~ 256`**（注意上限是 `2^8 = 256` 才是 100% 纯高电平直流，`255` 还会残留 `1/256` 的低电平窄脉冲！）；
- **极性陷阱**：模拟电路里常见用 **PNP 三极管或 P-MOSFET** 做高端开关控背光（低电平导通、高电平截止）。此时 `duty=255` 实际只有 `1/256 ≈ 0.4%` 亮度，屏幕极暗；把逻辑取反（`duty = 256 - raw`，即 `duty=0` 最亮、`duty=256` 全灭）才真正对应 `0% ~ 100%` 亮度。

### 5.2 SPI + DMA（27MHz 刷彩屏）
SPI 是一种同步串行总线，最核心的信号就两根线：
- **SCLK**（时钟）：主机发出方波脉冲，每跳变一次传 1 bit；
- **MOSI**（主发从收）：主机在时钟边沿前把数据位放到总线上，屏幕在时钟边沿采样。

算一笔带宽账（工程里非常重要）：
- 屏幕分辨率 `240 × 240 = 57,600` 像素；
- 每个像素用 **RGB565**（红 5 bit + 绿 6 bit + 蓝 5 bit = 16 bit = **2 字节**）；
- 一整屏数据量：`57,600 × 2 = 115,200 字节 = 921,600 bit`；
- 在 `27 MHz` SPI 时钟下，传一整屏的理论耗时：`921,600 / 27,000,000 ≈ 34.1 ms`（实测 `34.7 ms`，跟理论值几乎严丝合缝！）。
- 如果只重绘有变化的区域（如转圈动画只占 60 行），每帧只需传 `~8ms`，轻松跑满 20fps。

ESP32-C3 的 GPSPI 单次 DMA 传输硬件上限是 18-bit 长度寄存器（约 32KB），所以 `panel.c` 里按每块 `32,640 字节`（正好是 `240 × 2 × 68` 整数行）把整帧自动切块连续发给屏幕。

## 6. Flash 布局与启动流程（为什么刷机不会弄丢原厂相册）

ESP32-C3 上电后的接力启动顺序：

```text
  [1] 片内 Mask ROM（出厂固化，永远刷不坏）
       │ 检查 GPIO9：低电平 -> 等待 esptool 刷机；高电平 -> 读 Flash 0x0
       ▼
  [2] 0x000000  bootloader.bin（二级引导，~21KB）
       │ 初始化 Flash 为 DIO @ 80MHz，读取 0x8000 分区表
       ▼
  [3] 0x008000  partition-table.bin（分区表，3KB）
       │ 找到 factory app 分区（从 0x10000 开始，大小 3MB）
       ▼
  [4] 0x010000  agy_tv.bin（我们的固件，~450KB，含 ~190KB 中文字库）
       │ FreeRTOS 启动，调用 app_main()
```

对照原厂 4MB Flash 的完整布局：

```text
0x000000 ┌────────────────────┐
         │ Bootloader (21KB)  │ ◄─ 本项目刷写
0x008000 ├────────────────────┤
         │ Partition Table    │ ◄─ 本项目刷写
0x009000 ├────────────────────┤
         │ 原厂 NVS (WiFi配置) │ ◄─ 不碰！完整保留
0x010000 ├────────────────────┤
         │ agy_tv.bin (450KB) │ ◄─ 本项目刷写（只用到 ~0x81000）
         │ (空闲 ~2.5MB)      │
0x310000 ├────────────────────┤
         │ 原厂 SPIFFS (相册) │ ◄─ 不碰！完整保留
0x400000 └────────────────────┘ (4MB 结束)
```

因为 Mask ROM 永远不可擦写，**只要芯片物理没烧毁，软件怎么刷错都不会真正「变砖」**，随时可以重新进入下载模式刷回本项目固件或 `backup/esp32c3_original_4MB.bin` 原厂备份。
